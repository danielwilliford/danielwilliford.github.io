One minute version

From chatbot demo to AI operations.

I built a small but complete service that turns ambiguous business processes into controlled agentic workflows. It exposes API endpoints, uses LangGraph for stateful routing, validates outputs with eval gates, records traces and artifacts, requires human approval, and keeps profile mutation disabled behind dry run only apply controls.

The pattern maps directly to enterprise FDE work: discover a workflow, identify data and policy sources, define the decision boundary, wrap the agent in service contracts, add observability and approval gates, and package the result so delivery teams can reuse it.

Problem

Most AI demos stop at chat. Real teams need workflow systems.

Forward deployed AI work means taking messy intake, policies, files, systems, stakeholders, and human review steps and turning them into a repeatable service. That service needs retrieval, tool boundaries, evals, traces, artifacts, governance, and clear acceptance gates.

System

A service wrapper around bounded agentic workflows.

The service includes a claims/policy workflow, a graph catalog, and an operational profile validation chain. It backs up relevant surfaces, runs deterministic checks, emits artifacts, blocks unsafe requests, and stops at human approval.

Safety and controls

The control chain is the product.

Validation before approval

Profile validation requires backups, file/index checks, memory hygiene scans, grader execution, and JSON/Markdown reports before approval.

Strict approval

Approval checks run type, artifact presence, classified findings, detailed notes, and exact confirmation phrase. Numeric scores appear only when the rubric is published beside them.

Dry run apply gate

Patch manifest schema, allowed roots, symlink rejection, target path checks, audit records, and real mutation disabled by design.

Production posture

The service exposes the controls a delivery team would inspect.

The case study shows the operational contract: API surface, LangGraph state, required artifacts, strict approval, dry run apply behavior, audit records, and test coverage. The missing production pieces are named as implementation steps, not left as vague risk.

  • Move run storage from demo scope to SQLite or Postgres when persistence is required.
  • Keep real mutation disabled until patch preview, rollback, second approval, and deployment checks are in place.
  • Use traces, artifacts, eval gates, and audit records as acceptance evidence before rollout.
  • Reuse the pattern for claims, policy, compliance, support, and document workflows where trust depends on inspectable handoffs.
