Problem

Useful research systems fail when source hygiene is loose.

Before agents can summarize or reason over a corpus, sources need stable metadata, duplicate detection, provenance, review status, and strict write boundaries. Otherwise the system accumulates stale notes, duplicate PDFs, orphaned hypotheses, and unverifiable claims.

System

Make ingestion deterministic before analysis starts.

The pipeline validates source metadata, derives a stable source identity, writes reviewable artifacts, updates a candidate queue, records archive logs, and refuses unsafe write paths. It is intentionally boring infrastructure: the part that makes later AI work auditable.

Architecture

Ingestion flow with failure gates.

01 Source intakeAccept a local file or metadata only source reference with title, authors, year, source type, URL/path, and optional tags.
02 ValidateRun schema checks for required fields, enum values, file size, checksum shape, DOI/arXiv shape, and unexpected legacy fields.
03 NormalizeGenerate an ASCII safe slug, deterministic source ID, checksum, and canonical source metadata packet.
04 DeduplicateDetect existing source references and slug collisions, then update verification metadata instead of creating duplicate artifacts.
05 Write safelyWrite ingestion notes, review queues, and archive logs only inside approved project/research directories.
Implementation sketch

Public proof without exposing private research strategy.

This is a good first GitHub candidate because it demonstrates software hygiene without publishing private finance algorithms, datasets, strategy logic, account state, or proprietary research notes.

source_metadata:
  source_id: deterministic_uuid(title, source_ref, checksum)
  type: book | paper | report | slide_deck | blog_post | thesis
  title: required
  authors: non_empty_list
  year: bounded_integer
  source_url_or_path: required
  checksum_sha256: lowercase_hex

gates:
  validate_metadata before writes
  reject oversized files
  reject unexpected legacy fields
  detect duplicate source_ref
  block writes outside approved directories
Verification evidence

The tests cover the boring failure modes that matter.

The local test surface covers schema validation, slug generation, hypothesis/review IDs, status enums, deduplication, CLI fail closed behavior, oversized file rejection, and path boundary enforcement.

pytest evidence:
  schema fixtures validate and fail as expected
  bad years, missing authors, empty authors rejected
  oversized files rejected before artifact writes
  unexpected legacy fields rejected
  slug generation is deterministic
  review IDs remain monotonic
  duplicate source references are detected
  path traversal and outside vault writes are blocked
  dry run validates without writing artifacts
Why it matters for applied AI

Source hygiene is an AI reliability feature.

  • Agents can retrieve and cite durable source records instead of loose local notes.
  • Research artifacts carry provenance and review state before synthesis starts.
  • Duplicate and stale inputs are handled as operational failures, not hidden in generated prose.
  • Private domain logic stays private while the reusable ingestion pattern can be reviewed publicly.
Publication boundary

What stays out of the public repo.

  • No private vault paths, datasets, generated research notes, trading logic, strategy parameters, credentials, or account state.
  • No domain specific alpha claims or market performance claims.
  • Public copy should contain the ingestion utility, schema fixtures, tests, README, and sanitized sample metadata only.
