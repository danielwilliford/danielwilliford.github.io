One minute version

A finance copilot is useful when it improves research, not when it pretends to be a trading bot.

The system helps a human operator research candidates, run backtests, compare A/B variants, review market/news/macro inputs, plot results, and produce inspection packets. It can run overnight style research loops against a vector knowledge base and existing pipelines, then surface candidates, failures, daily brief items, feature notes, and best run summaries for review.

Promotion is controlled: candidates must carry provenance, freshness, validation status, limitations, run artifacts, and a clear human decision boundary. The LLM layer helps research, summarize, monitor, and manage sandbox trials; any live trading belongs to separate deterministic execution software after explicit human review.

Problem

Finance exposes the failure modes of AI systems quickly.

LLMs can hallucinate facts, summarize stale reports, overfit backtests, or confuse a research candidate with an action. In finance, those are not cosmetic errors. The system has to separate data ingestion, research generation, strategy code, sandbox trials, validation, review, and execution authority.

System

The copilot manages research records and paper trials, not live orders.

The dashboard frames ML outputs, research briefs, backtest runs, paper portfolio experiments, and feed derived ideas as candidates with source links, freshness, model context, reason codes, warnings, and review status. A person decides what to investigate, reject, promote, or translate into deterministic bot changes.

Quality gates

How the system pushes back on hallucination prone workflows.

Freshness checks

Every candidate needs an as of timestamp, data source state, and warning path when prices, reports, targets, or model inputs are stale or unavailable.

Evidence requirements

Research outputs must point to source material, generated artifacts, report paths, or validation runs instead of relying on model confidence alone.

Failure labeling

Missing data, stale quotes, unavailable reports, leakage risk, and unsafe live mutation attempts are surfaced as decision blockers, not hidden behind polished copy.

Data and dashboard operations

The useful work is cleaning, validating, routing, and explaining the data before a model ever speaks.

Market/feed ingestion

Sanitized market, news, and macro style feeds are normalized before analysis, with provenance, freshness labels, retry/degraded states, and broker paths excluded.

Coverage gates

Backtests and research packets carry data provenance, coverage checks, leakage guards, cost assumptions, source freshness, and reproducible output artifacts.

Research coverage API

Backend scanners normalize report status, source counts, freshness windows, daily brief readiness, and missing/stale states so the UI displays reviewability instead of doing ad hoc research.

Typed dashboard layer

Finance views use typed query/cache/polling patterns, dry run job submission, source health badges, timeout handling, and degraded state labels for operator trust.

Managed service recovery

An ad hoc finance bridge was moved behind a managed user service with health checks and explicit endpoint mapping, turning dashboard support into an operable service surface.

API failure semantics

Research coverage endpoints return degraded packets for missing or unavailable inputs instead of inventing data or turning routine data gaps into unhelpful 500s.

Throughput hygiene

Batch and dashboard paths are treated as data plumbing first: normalize payloads, cache predictable reads, expose source health, and keep writes dry run by default.

Database readiness

The resume layer surfaces SQLite, PostgreSQL, Parquet, PyArrow, and typed models because the practical work is cleaning, shaping, and serving trustworthy data.

Architecture

Research generation, sandbox testing, deterministic validation, dashboard status, and human decision boundaries.

Standalone mode

Useful without an autonomous agent.

As a dashboard, the copilot gives a human operator a structured way to review signals, research gaps, plots, model context, source freshness, risk warnings, and sandbox run history. It is decision support, not automation theater.

Agent assisted mode

Useful inside a controlled agent workflow.

Agents can run research briefs, backtest candidates, compare A/B variants, review prior notes/vector context, summarize best results and features, and propose watchlist questions. Deterministic checks decide whether outputs are usable enough to promote to human review.

Safety and controls

The approval boundary keeps sandbox research separate from live action.

Advisory only boundary

Paper portfolios can test feature, optimization, rebalance, and allocation ideas; the LLM layer does not place live trades, and production bot changes require explicit approval.

Validation discipline

Checks include freshness, lookahead/leakage, walk forward framing, survivorship, slippage, transaction costs, and reproducible artifacts where applicable.

Honest limitations

The case study avoids performance flexing and states where option PnL realism, liquidity, spread, and execution modeling would need more work.
